# html/scripts — agent notes

`html` (formerly `html2md`) is the repo's first **TWO-master** skill (CLAUDE.md §2). Proprietary,
All Rights Reserved (embeds proprietary docx/pdf code — see ../NOTICE).

**Naming caveat (post-rename):** the skill + user-facing launcher is `html` — the launcher is
the **extensionless** `scripts/html` (NOT `html.py`: `scripts/` is `sys.path[0]`, so a `html.py`
— or renaming the package dir to `html` — would shadow the stdlib `html` module that `acquire.py`
and the pdf-mastered `web_clean/preprocess.py` import). The **internal Python package keeps its
`html2md` name** for the same reason; so `from html2md import …`, `import html2md`, the
`html2md/` package dir, `discover -s html2md/tests`, and the docx-mastered `html2md_core.js`
replica all retain the `html2md` token by design.

  **Encapsulation:** the `__main__` block calls `cli._load_skill_env()` BEFORE `main()` —

  `~/.claude/skills/html` symlink) gets the skill's config transparently, no machine-global

  **OP3 `get` (obsidian-llm-wiki TASK 072 / Q-072-1):** `get` verb-intercept in `main` → `_get_main`
  (`html get URL (OUTPUT_PATH | --stdout)`) + `_parse_headers` + `_VERB_HELP` — raw bytes through
  `acquire._assert_safe_target` then `acquire._http_get_bytes`, the SAME two the text path uses, with
  **no** content-type layer above them. It exists because `_fetch_lite_html` deliberately refuses
  `%PDF-` (turndown dies on binary), which left a caller wanting the bytes with nothing to shell out
  to — it fell back to an unguarded `urlopen`. The refusal it skips lives in a CALLER of the ladder,
  not in the ladder.

  Design decisions, with the reason (the reason is the part that stops them being reverted):
  (a) **dedicated parser**, not `build_parser()` — a byte primitive should not inherit ~30 conversion
  flags it must then reject one by one, the way `_fetch_main` rejects `--search`; this follows the
  `_login_main` primitive-verb precedent, so it is house-consistent, not a deviation.
  (b) `OUTPUT_PATH` is a **FILE**, not `OUTPUT_DIR` — slug derivation is a conversion concern.
  (c) `_GET_DEFAULT_MAX_BYTES = 64 MiB` — a **finite** default, unlike the conversion flags' `None`,
  because an unbounded arbitrary-binary download is a DoS foot-gun. The body is buffered, so the cap
  is also the memory bound.
  (d) `_errors.add_json_errors_argument`, **not** a hand-rolled `--json-errors`: the helper also
  monkey-patches `parser.error`, so argparse's OWN usage errors emit the envelope. `get` is the one
  verb whose documented consumer is another program parsing stderr as JSON.
  (e) argparse `SystemExit` is caught and RETURNED — and the guard is `_EXIT_USAGE if exc.code is
  None else int(exc.code)`, **never** `exc.code or _EXIT_USAGE`: `--help` exits 0, 0 is falsy, and
  the naive form turned a successful `--help` into exit 2.
  (f) **scheme validated in `_get_main`**, before the ladder — otherwise `html get /tmp/x.pdf` reports
  exit 10 `refused non-http(s) target`, i.e. a caller typo reads as an SSRF block in the consumer's
  logs (and `_redact` mangles the path). Caller error = 2; security refusal = 10; keep them apart.
  (g) **symlink / directory OUTPUT_PATH refused.** `write_bytes` opens `'wb'`, which FOLLOWS a
  symlink — verified exploitable pre-fix: `out.bin -> SENSITIVE.txt` was overwritten with remote
  bytes and the link left intact, i.e. undetectable. This is the only verb that writes unsanitized
  remote bytes to a caller-named path.
  (h) **atomic write** (`.part` + `os.replace`) so a crash cannot leave a truncated artifact the
  caller has no way to detect. A refusal leaves a pre-existing OUTPUT_PATH **untouched, not removed**
  — `get` never unlinks a file it did not create. (The earlier docs claimed "leaves NO file"
  unconditionally; that was false whenever the caller pre-created the path, which the intended
  consumer does with `mkstemp`.)
  (i) ★ `--deadline` (default 300 s, `(0, 3600]`) is the TOTAL wall clock and the number a consumer
  sizes its `subprocess(timeout=…)` against. `--timeout` is PER OPERATION and bounds **nothing** in
  total — MEASURED: a 5-hop redirect chain stalling *below* the timeout ran 2.4x the per-op budget
  (the factor is `max_redirects + 1`, multiplied again by each retry pass ⇒ `60 x 6 x 4 = 1440 s` at
  shipped defaults, against a `~243 s` we had DOCUMENTED), and a body dripping one byte per 1.6 s
  returned OK after 12.85 s against a 2 s timeout, time-unbounded in principle because `--max-bytes`
  caps SIZE and never TIME. The deadline is enforced INSIDE the ladder (`_http_get_bytes`,
  `deadline_s=`) at **both** the redirect loop and the chunk loop — a check between retries only
  would bound neither. `deadline_s=None` keeps the historical behaviour for existing callers.
  Refusal is exit 10 with `details.kind == "deadline"`.
  (i-bis) `--timeout` bounded to `(0, 300]` and `--retries` to `0..10`: `type=float` accepts `0`,
  `-5`, `nan` and `1e9`.
  (k) ★ **Refusal tests assert `details.kind`, never bare `rc == 10`.** With `_is_ssrf_blocked`
  disabled the original tests still PASSED — the mutant egressed into RFC-1918 and got a real
  `HTTP 404`, and `_get_main` maps every FetchFailed to 10, so the assertion could not tell a
  security refusal from a ConnectError. The most security-load-bearing property of the change had a
  VACUOUS regression test. `kind` discriminates (`refused` / `deadline` / transport), and
  `test_the_refusal_assertion_can_actually_fail` is the non-vacuity control.
  (l) broken pipe on `--stdout` is exit **141** (128+SIGPIPE), not 0 and not `Internal error:
  BrokenPipeError`: the consumer holds a PREFIX, and reporting success there is the undetectable
  truncation the file path exists to exclude.
  (j) `_parse_headers` checks control chars on the **RAW** item **before** stripping — checking after
  `.strip()` is a real bypass and it shipped in the first draft (`"X-Bad\n: c"` → `"X-Bad"`, newline
  gone before the test saw it).

  **Egress posture (fixed 2026-08-06, applies to the WHOLE skill, not just `get`):** the client is
  built `trust_env=False` with `proxy=_proxy_setting()` (`acquire.py`, `$HTML_PROXY`). Until then
  the DNS pin was **decorative** — `httpx` honours `trust_env` by default, so an ambient proxy
  (including the macOS System Configuration one, invisible to `env | grep -i proxy`) connected to
  the PROXY, which resolved the target itself, and `_pin_host_addrs`' `getaddrinfo` override never
  fired. Measured: pinning `example.com` to a blackholed `192.0.2.1` returned **HTTP 200** proxied
  vs `ConnectTimeout` direct. Side effects of `trust_env=False` are deliberate and were checked
  against this machine: `.netrc` (absent) and `SSL_CERT_*` (unset) are also ignored — the first is
  a small security gain (no Basic-auth replay onto a redirect target).
  ⚠️ Two residuals stay, and both are in SKILL.md §5: setting `HTML_PROXY` re-opens the window by
  construction (one-time stderr notice when it does), and under a **fake-IP resolver** — which is
  what the shipped `HTML_SSRF_ALLOW_NETS=198.18.0.0/15` default exists for — the pin binds the
  *synthetic* address, with the synthetic→real mapping owned by the proxy tool.
  Pinned by `html2md/tests/test_proxy.py` (10 tests, incl. an ambient-`HTTP_PROXY`-is-ignored case
  and a non-vacuity check on the kwarg spy).

  Pinned by `html2md/tests/test_get.py` (31 tests) — incl. an **AST-based** guard that `cli.py`
  imports/calls no HTTP primitive, with a non-vacuity test proving the AST logic fires on a real
  violation. That guard is AST and not grep on purpose: the grep version failed on `_get_main`'s own
  docstring, which names `urlopen` to explain why the verb exists.
- `html2md/acquire.py` — FC-1: input dispatch + fetch. Offline 022-02; URL 022-06.
  **TASK 023 = the resilient fetch ladder (all html-owned, NOT gated):**
  `_acquire_url` is a **tier ladder** (`_url_tiers`: auto local-first `lite→chrome→remote`;
  `jina`/`remote` remote-first + local fallback; `lite`/`chrome` single tier; `allow_chrome=False`
  drops chrome for attacker-influenceable search results). Tiers: `_tier_lite`/`_tier_chrome`/
  `_tier_remote`. Remote tier `_fetch_remote_html` = **vendor-agnostic** provider loop
  (`_remote_providers`/`_build_reader_request`; `jina` default, `HTML_READER_URL`/`_PROVIDERS`
  for self-hosted). Classification: `_TierUnavailable` (escalate) vs terminal `FetchFailed`;
  one `FetchFailed(kind=all_engines_failed, details.tried=[…])` (URL-free trace) when exhausted.
  Privacy: target public-IP gate + `--no-remote` BEFORE any remote request; `_assert_safe_target`
  (CR/LF guard). **SSRF gate (`_is_ssrf_blocked`/`_host_is_public`/`_assert_public_http`):** keeps
  Python's maintained `ip.is_private` (+ loopback/link-local/reserved/multicast/unspecified) and
  SUBTRACTS an **explicit** carve-out — `HTML_SSRF_ALLOW_NETS`, **no code default**: unset OR
  `""` → NO carve-out (strict, fail-safe); a CIDR list → exactly those ranges. The shipped
  `.env.example` sets `198.18.0.0/15` (RFC 2544; `*.eth.limo`-style local-resolver mappings) so the
  auto-loaded `.env` re-allows it. IPv4-mapped/translated IPv6 unwrapped before the family-matched
  check; carve-out read lazily (the shim loads `.env` after import). Search:
  `_search_providers`/`run_search` (s.jina.ai default; per-result via the ladder). Trust-markdown:
  `_split_remote_markdown` + `_LOOKS_HTML` fallback.
  Heavy deps (httpx/trafilatura/playwright) imported lazily INSIDE functions only.
  **TASK 024 = authenticated Chrome (all html-owned, NOT gated):** `_fetch_chrome_html(url, opts)`

  `route` aborts non-public requests, fail-closed, per-host getaddrinfo cache) installed BEFORE
  goto, off-target-public-redirect refusal (`_registrable` eTLD+1), `--max-bytes` parity on the
  rendered body, stale-session `is_login_wall`→`auth_required`. Auth context from
  `_chrome_auth.resolve_context_kwargs` (storage_state / cookies via `_cookies` / persistent
  profile). `_chrome_scroll` (bounded by passes + `_CHROME_SCROLL_BUDGET_S`). `_login_render`
  (headful mint, `umask 0o077` → 0600). `_import_sync_playwright` is the test seam.
  **TASK 025 (LIGHT):** both mint + render launch via `_launch_chrome_browser` /
  `_launch_chrome_persistent` — prefer the user's **real system Chrome** (`channel="chrome"`) with
  bundled-Chromium fallback (R10), pass `_CHROME_LAUNCH_ARGS`
  (`--disable-blink-features=AutomationControlled`), and `add_init_script(_WEBDRIVER_MASK_JS)` to
  mask `navigator.webdriver`. Fixes native logins (X email/password) being flagged as bots; Google
