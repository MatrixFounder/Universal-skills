# Постановка: поддержка Obsidian-заметок в скиле `docx`

**Статус:** черновик к реализации
**Дата:** 2026-08-13
**Скил:** `docx` (`~/.claude/skills/docx`), точка входа `scripts/md2docx.js`
**Автор постановки:** по итогам реального прогона «конвертировать заметку вольта в .docx»

---

## 1. Контекст

Скил `docx` конвертирует **Markdown** → `.docx` и делает это хорошо. Но заметка Obsidian —
это не CommonMark, а его диалект: YAML-фронтматтер, `![[embed]]`, `[[wikilink]]`, коллауты,
`$math$`. Сегодня прогон вольтовой заметки через `md2docx.js` завершается **exit 0 и
валидным `.docx`**, в котором часть содержимого потеряна без единого предупреждения.

Это худший класс дефекта: не падение, а тихая потеря данных при успешном коде возврата.

### Воспроизведение (эталон для регресс-теста)

```bash
node scripts/md2docx.js "<vault>/06 - Business Development/Yandex/Встреча по поддержке SpeechSense с Yandex.md" out.docx --page-size A4
# → exit 0, "Document generated at out.docx"
unzip -l out.docx | grep -c media      # 2  = каталог word/media/ + 1 png (только mermaid)
unzip -p out.docx word/document.xml | grep -c "Осипов"        # 0  — участники потеряны
unzip -p out.docx word/document.xml | grep -o "!\[\[[^]]*\]\]" # ![[yc-onprem-support-l1-l4.png]] …
```

## 2. Подтверждённые дефекты

Всё ниже проверено эмпирически на текущей версии скила, а не выведено из чтения кода.

| # | Дефект | Механизм | Наблюдаемый результат |
|---|---|---|---|
| **D1** | Фронтматтер молча отбрасывается | `md2docx.js:56` — `rawMarkdown.replace(/^---\n[\s\S]*?\n---\n/, '')` | Метаданные, живущие **только** в YAML, исчезают из документа. В эталоне это `participants:` (5 человек) — в теле заметки их нет вообще, `grep "Осипов"` по `document.xml` даёт 0. Также теряются `tags`, `published`, `URL`, `sources`. |
| **D2** | `![[embed]]` не распознаётся | `marked.lexer('![[pic.png]]')` → **`text`**-токен, не `image` | Оба слайда встречи не вставлены; вместо них в документе литеральная строка `![[yc-onprem-support-l1-l4.png]]`. Изображений в пакете 1 (сгенерированный mermaid) вместо 3. |
| **D3** | `[[wikilink]]` не распознаётся | то же — `text`-токен | В документ уезжают сырые `[[слаг\|Подпись]]`, включая весь футер «Ключевые сущности» (13 ссылок) и `[[_raw/…\|_raw/….md]]`. |
| **D4** | Пробел в пути к картинке = тихая потеря | `marked.lexer('![a](/tmp/my folder/pic.png)')` → **`text`**-токен | Обычный Markdown (не Obsidian!) с пробелом в пути к изображению конвертируется без ошибки и **без изображения**. Путь вольта содержит пробелы всегда (`Mobile Documents`, `06 - Business Development`), так что это срабатывает на каждой заметке. |

### Что при этом работает и трогать не надо

Проверено на тех же данных:

* `resolveLocalImagePath()` уже делает `decodeURI(rawHref)` → **percent-encoded** пути (`%20`) работают;
* marked корректно разбирает **angle-bracket destination**: `![a](</tmp/my folder/pic.png>)` → `image`-токен с href, содержащим пробелы. Значит **D4 чинится на стороне производителя разметки**, ядро `md2docx.js` менять не требуется;
* пути к картинкам резолвятся относительно каталога входного `.md` (`inputDir`, строка 54);
* mermaid-блоки рендерятся и вставляются;
* `--page-size A4` корректно масштабирует изображения и таблицы.

### Чего в `md2docx.js` нет вовсе (grep = 0)

* математика — `$…$` / `$$…$$` уезжают текстом (`katex`/`mathml` не упоминаются);
* коллауты Obsidian — `> [!warning] Заголовок` парсится как обычный `blockquote`, маркер `[!warning]` остаётся литералом.

## 3. Цель и границы

**Цель:** заметка из вольта Obsidian конвертируется в `.docx` без потери содержимого и без
ручной предобработки, одной командой.

**Не цель (сознательно вне рамок):**

* редактирование `.docx` обратно в заметку (обратный маршрут — отдельная задача);
* поддержка плагинов Obsidian (Dataview, Templater, Excalidraw-рендер);
* полноценный движок формул (см. R-3 в разделе рисков).

## 4. Предлагаемая архитектура

**Рекомендую: отдельный конвертер + тонкий флаг-обёртка.**

```
scripts/obsidian2md.js          ← НОВОЕ: Obsidian-разметка → чистый CommonMark
scripts/md2docx.js              ← +флаг --obsidian [--vault-root DIR]
```

* `obsidian2md.js IN.md OUT.md [--vault-root DIR] [--assets-dir DIR] [--frontmatter MODE] [--strict-assets] [--json-errors]`
  — самостоятельная утилита, ничего не знающая про OOXML.
* `md2docx.js … --obsidian [--vault-root DIR]` — прогоняет вход через `obsidian2md.js` во
  временный каталог и дальше работает как сейчас.

**Почему так, а не флагом внутри `md2docx.js`:**

1. Та же проблема один в один стоит перед соседними скилами — `pdf` (`md2pdf.js`),
   `pptx`, `marp-slide`. Отдельная утилита переиспользуется ими без копипасты; флаг — нет.
2. Тестируется чисто текстово (`.md` → `.md`), без сборки и распаковки `.docx`.
3. Повторяет уже принятый в скиле паттерн композиции: `html2docx.js` + вспомогательные
   `_html2docx_preprocess.js` / `_html2docx_walker.js`.

**Альтернатива (отклонена):** реализовать Obsidian-синтаксис как расширения `marked`
(custom tokenizer). Мощнее, но привязывает логику к внутренностям `md2docx.js` и не
переиспользуется другими скилами. Если решите пойти этим путём — вынесите tokenizer в
отдельный модуль `_obsidian_tokens.js`, чтобы он оставался общим.

## 5. Функциональные требования

### FR-1. Фронтматтер (закрывает D1)

Режимы через `--frontmatter MODE`:

| MODE | Поведение |
|---|---|
| `strip` | как сейчас — срезать молча |
| `render` **(default)** | срезать и **пере-издать значимые ключи прозой** сразу после `H1` |
| `table` | то же, но двухколоночной таблицей ключ/значение |

Для `render` минимальный набор с локализуемыми подписями:
`participants` → **Участники** (маркированный список), `tags` → **Теги** (через запятую),
`author`, `published`/`date`, `URL`/`source`. Ключи служебные для индекса
(`type`, `slug`, `vault_id`, `Created`, `Updated`, `sources`, `tldr`) — **не выводить**:
`tldr` дублирует тело, остальное — машинное.

Набор ключей и подписи вынести в конфиг-константу, не в тело функции.

### FR-2. Встраивания `![[…]]` (закрывает D2)

| Что во входе | Что на выходе |
|---|---|
| `![[image.png]]` | `![image](<разрешённый путь>)` |
| `![[image.png\|300]]` | то же + ширина 300 px (см. FR-6) |
| `![[image.png\|100x50]]` | то же + ширина/высота |
| `![[Заметка]]` (трансклюзия) | по умолчанию — строка-ссылка «*См. заметку «Заметка»*»; при `--transclude` — врезка тела заметки с понижением уровня заголовков и **защитой от циклов** (глубина ≤ 3, множество посещённых путей) |
| `![[file.pdf]]`, `![[file.pdf#page=3]]` | строка-ссылка с именем файла (вставлять PDF нельзя) |
| `![[audio.mp3]]`, `![[video.mp4]]` | строка-ссылка с именем файла |

### FR-3. Ссылки `[[…]]` (закрывает D3)

| Что во входе | Что на выходе |
|---|---|
| `[[target\|Подпись]]` | `Подпись` (простой текст) |
| `[[target]]` | последний сегмент пути `target` |
| `[[target#Заголовок]]` | `target → Заголовок` |
| `[[target#^block]]` | `target` |

Опционально `--links=text\|italic\|bookmark`: `bookmark` — резолвить во внутреннюю
гиперссылку `.docx`, если целевая заметка попала в документ через `--transclude`.
По умолчанию `text` — вне вольта wikilink смысла не имеет.

### FR-4. Разрешение путей к вложениям

Порядок, повторяющий поведение самого Obsidian:

1. `<vault>/.obsidian/app.json` → ключ `attachmentFolderPath`. Значение вида `./_attachments`
   означает «каталог рядом с заметкой» (именно так настроен эталонный вольт).
2. Каталог самой заметки.
3. Явный относительный/абсолютный путь из ссылки.
4. Поиск по имени файла в пределах `--vault-root` (у Obsidian имена вложений уникальны).
   Сравнение — с нормализацией **NFC** и case-fold: кириллица из macOS-путей приходит в NFD,
   наивное сравнение строк её не найдёт.
5. Не нашли → поведение по `--strict-assets`: без флага — плейсхолдер
   `*[изображение не найдено: X]*` + предупреждение в stderr; с флагом — ненулевой выход.

`--vault-root` не задан → искать вверх от заметки до каталога, содержащего `.obsidian/`;
не нашли — считать корнем каталог заметки.

### FR-5. Безопасные destination (закрывает D4)

Все пути, которые конвертер выпускает в Markdown, **обязаны** быть валидны для marked:
либо angle-bracket `![alt](<путь с пробелами>)`, либо percent-encoding. Обе формы уже
корректно доезжают до `resolveLocalImagePath()` (см. §2) — ядро не трогаем.

Дополнительно, **в самом `md2docx.js`** — страховка от тихой потери: если в исходнике
встречается `text`-токен, подходящий под `/!\[[^\]]*\]\([^)]*\s[^)]*\)/`, писать в stderr
предупреждение вида
`warning: image link with unescaped spaces was not parsed as an image: <фрагмент>`.
Это чинит D4 и для обычных (не-Obsidian) пользователей, которые пишут
`![](my folder/pic.png)` и получают документ без картинок.

### FR-6. Размер изображения из `|300`

Obsidian-хинт ширины пробросить в `md2docx.js`. Так как CommonMark его не выражает,
предлагаю передавать через alt-текст с зарезервированным префиксом
(`![w=300|alt](…)`), а в `buildImageRun()` распарсить и применить как верхнюю границу,
не отменяя существующее вписывание в геометрию страницы (ширина = `min(хинт, maxWidthPx)`).

### FR-7. Коллауты Obsidian

`> [!type] Заголовок` → абзац-заголовок жирным (`**Заголовок**`, при отсутствии — подпись
по типу: `[!warning]` → «Внимание», `[!note]` → «Заметка») + остальное тело коллаута
обычным blockquote. Маркер `[!type]` не должен доезжать до документа литералом.
Достаточно словаря типов Obsidian по умолчанию + fallback на сам тип.

### FR-8. Мелкий синтаксис

| Вход | Выход |
|---|---|
| `==выделение==` | `**выделение**` |
| `%%комментарий%%` | удалить целиком |
| `#инлайн-тег` | удалить или оставить текстом — флаг `--inline-tags=strip\|keep` (default `strip`) |
| `- [ ]` / `- [x]` | `☐` / `☑` + текст (docx-чекбоксов в списках у `md2docx.js` нет) |

## 6. Требования к соответствию конвенциям скила

Не «пожелания», а условия приёмки — иначе утилита выпадет из общей рамки:

1. **Ошибки** — через существующий конверт: `--json-errors` даёт одну строку JSON в stderr
   вида `{v:1, error, code, type?, details?}` (см. `scripts/_errors.py`). Для JS-скрипта —
   тот же конверт, что у `html2docx.js`.
2. **Коды выхода** — по образцу `docx_replace.py`: `0` успех, `1` I/O, `2` невалидный
   аргумент, `6` отказ перезаписать вход тем же путём (`SelfOverwriteRefused`).
   Плюс новый — на `--strict-assets` при ненайденном вложении (предлагаю `8`
   `AssetNotFound`, свободен).
3. **Локальные зависимости** — только `scripts/node_modules`, ничего глобально.
   Если появится Python-часть — самобутстрап через `_venv_bootstrap.py`.
4. **Документация** — обновить `SKILL.md`: §2 Capabilities, §4 Script Contract (сигнатура
   команды), §10 Quick Reference (строка «Obsidian-заметка → .docx»), §1 Red Flags
   (добавить «я просто прогоню вольтовую заметку через md2docx.js» → **WRONG**, с описанием
   D1/D2 и тем, что exit 0 ничего не гарантирует).
5. **Тесты** — в `scripts/tests/` по образцу `test_md2docx_pagesize.py`, фикстуры в
   `examples/`. Гейт `validate_skill.py` должен оставаться зелёным.

## 8. Риски и открытые вопросы

* **R-1. Двоякость `![[Заметка]]`.** Трансклюзия — самая спорная часть: для протокола
  встречи она не нужна, для MOC-заметки критична. Поэтому за флагом, а не по умолчанию.
  Решите, нужна ли она вам вообще — если нет, FR-2 упрощается вдвое.
* **R-2. Порядок разрешения имён.** Правило Obsidian «уникальное имя вложения по вольту»
  на большом вольте даёт коллизии. Поиск по вольту — последний шаг, и при >1 совпадении
  надо писать warning с перечислением кандидатов, а не молча брать первое.
* **R-3. Математика.** `$…$` сейчас уезжает текстом. В скиле `pdf` формулы уже решены
  (пререндер KaTeX → MathML, `md2pdf.js`). Для docx честных варианта два: OMML через
  `docx`-библиотеку или растр формулы в png. Предлагаю **вынести за рамки этой задачи**
  и завести отдельно — иначе она утопит остальное.
* **R-4. Локализация подписей** (`Участники`, `Теги`, `Внимание`). Сейчас скил
  англоцентричен. Минимум — константа-словарь с `--lang ru|en`, чтобы не зашивать русский
  в код.
