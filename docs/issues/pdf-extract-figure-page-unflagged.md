# PDF-EXTRACT-FIGURE-PAGE-UNFLAGGED — страница, состоящая из одной схемы, не помечается: колонтитул выбивает её из-под порога в 10 символов

> **Resolved 2026-08-29.** В дамп добавлены постраничные **`image_coverage`** и
> **`vector_coverage`** (доли площади листа) и отдельный флаг **`figure_dominant`**:
> `(image_coverage + vector_coverage) >= 0.25 AND char_count < 200`, пороги вынесены в
> константы `_FIGURE_COVERAGE_THRESHOLD` / `_FIGURE_CHAR_THRESHOLD` рядом с
> `_SCANNED_CHAR_THRESHOLD` и описаны в docstring. Учтено уточнение от 2026-08-29: считается
> **сумма** растровой и векторной площади, иначе векторная фигура пропускается.
> `vector_coverage` — не сумма bbox'ов (у линовки площадь bbox'а ≈ 0), а площадь **кластеров**:
> path-объекты наносятся на сетку ~4 pt, ищутся связные компоненты (8-связность), каждая
> вносит свой bbox; это и даёт замеренные 42–85 % на страницах с таблицами, где несущим
> становится порог по `char_count`.
> Страницы перечислены в топ-левел **`figure_pages`** с предупреждением на stderr;
> **код возврата не тронут**, `doc_scanned` / `scanned_pages` не расширены. `figure_dominant`
> и `scanned` сделаны **взаимоисключающими**: скан уже помечен и чинится иначе (OCR, а не
> выгрузка картинки) — инвариант `figure_pages == [n for n in pages if figure_dominant]`
> сохраняется.
> Документация: `references/pdf-to-markdown.md` §3.4 («страница-иллюстрация ≠ скан», таблица
> замеров, что делать), §2, §5, §6 (почему подъём порога в 10 символов — неверный ремонт),
> SKILL.md, `scripts/.AGENTS.md`. Оговорка «пометить — половина решения, картинку всё равно
> надо выгрузить (`pdf-13`)» вписана и в §3.4, и в honest scope скрипта.
> Фикстура `figure.pdf` — по странице на каждый замеренный случай: (1) проза, (2) растровая
> схема под одним колонтитулом (35 %/33 символа — ровно тот случай, который старая эвристика
> пропускает), (3) **векторная** схема, изображений ноль (31 %/90 символов), (4) скриншот
> рядом с живым текстом (14 %/1617) — контроль порога площади, (5) плотно линованная таблица
> (58 %/1127) — контроль несущего порога по тексту.
> Тесты: `TestFigurePages` (14 кейсов, включая границы предиката, дизъюнктность со `scanned`,
> вырожденные входы и отдельный тест на то, почему меряются кластеры, а не сумма bbox'ов) +

> порога по тексту, откат к старой эвристике и замена кластеризации на счёт клеток — все

## Симптом

Страница, всё содержимое которой — одна большая схема (архитектурная диаграмма, блок-схема,
экспортированный Mermaid/PlantUML), приходит в дамп как обычная текстовая страница с
несколькими десятками символов служебного текста. Флага нет, кода возврата нет:

```
page 4 -> chars: 62 | has_images: True | scanned: False
page 4 text: 'Конфиденциально ООО «...»\n4'
doc_scanned: False | scanned_pages: []   | exit 0
```

Агент, собирающий markdown из `text` (а это ровно то, что предписывает
`references/pdf-to-markdown.md` §2), получает страницу из одной строки колонтитула — и
**вся схема исчезает молча**. Ни `doc_scanned`, ни `scanned_pages`, ни exit `10` не
срабатывают, потому что документ в целом цифровой.

Это тот же класс отказа, который скилл декларирует закрытым («на скане pdfplumber отдаёт
пустой текст *молча* — `pdf_extract.py` вместо этого выходит с кодом 10»), только на уровне
отдельной страницы.

## Корневая причина

`_classify_page` — конъюнкция с **абсолютным** порогом:

```python
return char_count <= _SCANNED_CHAR_THRESHOLD and has_images   # 10
```

Сквозной колонтитул (гриф конфиденциальности, название компании, номер страницы) даёт
30–70 символов и гарантированно выбивает страницу из-под порога. Колонтитул есть практически
в любом корпоративном ТЗ, отчёте, whitepaper — то есть ровно в тех документах, где
страницы-иллюстрации и встречаются. Порог измеряет не то: значение имеет **доля страницы
под изображением относительно плотности текста**, а не абсолютное число символов.

## Воспроизведение

Проверено на четырёх документах от трёх независимых продюсеров. `old` — текущая эвристика,
`new` — кандидатный сигнал по площади в ПЕРВОЙ редакции (`img_coverage >= 0.25 and chars < 200`);
исправленная формула — в п. 2 «Путь исправления»:

| Продюсер | Страница | Доля площади под изображением | chars | `old` | `new` |
|---|---|---|---|---|---|
| Acrobat PDFMaker 23 для Word / Adobe PDF Library 23.3.20 | стр. 4 (архитектурная схема, PNG 2370×3368 px @ ~384 DPI) | **56.0 %** | 62 | не сработал | **сработал** |
| WeasyPrint 68.1 (синтетическая проба: картинка + строка колонтитула) | стр. 2 | **61.1 %** | 38 | не сработал | **сработал** |
| Google Docs Renderer | стр. 5 / стр. 6 (скриншоты внутри полноценного текста) | 15.1 % / 23.2 % | 1943 / 1459 | не сработал | не сработал — **верно** |
| WeasyPrint 68.1 (фикстура со **встроенным SVG**) | стр. 3 (векторный график, растра нет) | **0 %** изображений / **31.1 %** векторной краски | 117 | не сработал | **не сработал — ПРОПУСК** |

Текущая эвристика не сработала **ни на одной** странице всех четырёх документов. Кандидатный
сигнал в первой редакции (только площадь изображений) поймал две растровые страницы-иллюстрации,
корректно промолчал там, где картинка сопровождает живой текст, но **пропустил четвёртую строку**
— векторную фигуру. Исправленная формула (сумма растровой и векторной площади, см. «Уточнение»
в п. 2 ниже) закрывает все три положительных случая без ложных срабатываний.

```bash
python3 -c "
import pdfplumber
p = pdfplumber.open('doc.pdf').pages[3]
area = p.width * p.height
cov = sum(abs(i['x1']-i['x0'])*abs(i['bottom']-i['top']) for i in p.images) / area
print(round(cov,3), len((p.extract_text() or '').strip()))   # 0.56 62 -> схема, а не текст
"
```

## Путь исправления

1. Добавить в дамп на каждую страницу **`image_coverage`** (доля площади листа под
   изображениями, 0..1) — числовой факт, полезный сам по себе и не меняющий поведения.
2. Ввести отдельный флаг **`figure_dominant`** (рабочее имя) поверх существующего `scanned`:
   `(image_coverage + vector_coverage) >= T_cov AND char_count < T_chars`. Замеренная
   разделяющая пара — `0.25 / 200`; пороги вынести в константы рядом с
   `_SCANNED_CHAR_THRESHOLD` и вписать в docstring, как это сделано для порога сканов.

   > **Уточнение 2026-08-29, найдено при сборке SVG-фикстуры.** Первая редакция этой записи
   > считала только площадь изображений — и **пропускала страницу, где фигура векторная**
   > (встроенный SVG: 0 % растра, 31.1 % векторной краски, 117 символов). Считать надо сумму:
   > площадь изображений плюс площадь кластеров path-объектов. При этом порог по `char_count`
   > — **несущий**, а не косметический: на страницах с таблицами «векторная краска» (линовка)
   > занимает 42–85 % площади, и без ограничения по тексту сигнал сработал бы на 24 страницах
   > из 29 в здоровом документе. С порогом `< 200` символов там не срабатывает ни одна.
3. Предупреждение на stderr со списком таких страниц — по образцу существующего warning для
   `scanned_pages`. **Код возврата не менять**: exit `10` означает «весь документ — скан»,
   у страницы-иллюстрации в цифровом документе другой смысл; ломать контракт кода возврата
   ради нового сигнала нельзя.
4. `references/pdf-to-markdown.md` §3.4 — дописать этот случай: «страница-иллюстрация ≠
   скан», и что делать (выгрузить картинку через `pdf-13` либо прочитать страницу как
   изображение).
5. Держать заодно с `pdf-13`: пометить страницу — половина решения, вторая половина —
   извлечь картинку, иначе агенту нечего вставить в markdown.

## Обходной путь (до фикса)

Считать долю площади вручную (сниппет выше) либо просматривать страницы с
`has_images: true` и подозрительно малым `char_count` глазами через `preview.py`.

## Do-not

- **Не** поднимать `_SCANNED_CHAR_THRESHOLD` вместо введения сигнала по площади: порог
  измеряет не ту величину, а его подъём начнёт помечать сканами настоящие текстовые
  страницы с короткой подписью.
- **Не** записывать `figure_dominant` в `scanned` / `scanned_pages` и не расширять
  `doc_scanned`: это разные вещи, а `doc_scanned` + exit `10` — публичный контракт.
- **Не** считать проблему закрытой одной пометкой страницы: без выгрузки изображения
  (`pdf-13`) содержимое всё равно не попадёт в markdown.
- **Не** строить сигнал на одной лишь площади изображений (пропустит векторную фигуру) и
  **не** выбрасывать порог по `char_count` (даст 24 ложных срабатывания из 29 страниц на
  документе с таблицами) — обе величины замерены.
