# PDF-EXTRACT-VECTOR-COVERAGE-BACKDROP — `vector_coverage` считает подложку страницы графикой и насыщается в 1.0 на сплошном тексте

> **Resolved 2026-08-30.** `_vector_coverage` отбрасывает объекты-подложки перед
> кластеризацией: новый предикат `_is_backdrop` (константа `_VECTOR_BACKDROP_RATIO = 0.9`)
> исключает **незаштрихованные заливки** (`stroke=False, fill=True`) площадью от 90 % листа.
> Обводка не трогается: нарисованная рамка во весь лист — это чей-то элемент оформления, а не
> подложка, и остаётся в замере. Замер после фикса: на проблемном документе исправились все
> 29 страниц из 29, на трёх других документах от трёх других продюсеров **не изменилось
> ничего** (0 страниц) — фикс хирургический. Формулировка stderr-предупреждения
> `text_layer_lossy` поправлена заодно (см. «Побочная находка»). Тесты: `TestFigurePages`
> TC-FIG-13/14/15 + `TestLossyTextLayer` TC-LTL-15 на фикстуре `figure.pdf`, которой
> добавлены стр. 6 (проза на подложке — не помечать) и стр. 7 (реальная фигура на той же
> подложке — помечать). Мутационная проверка: 5 мутаций, все убиты.
> Гейты: `tests.test_pdf_extract` 98 OK, `test_e2e.sh` 90/90, `validate_skill.py` PASSED.

## Симптом

На 29-страничном документе Google Docs Renderer, состоящем из сплошной прозы,
`vector_coverage` равен **1.000 на всех 29 страницах** — включая страницы, где нет ни одной
линии и ни одной таблицы:

```
стр. 7: всего path-объектов = 1  ->  vector_coverage = 1.000, chars = 2552
```

Ни одна страница при этом не была помечена `figure_dominant` — но только потому, что её
спас порог по тексту. То есть конъюнкт по площади на таком продюсере не работал вообще.

## Корневая причина

Google Docs Renderer (и не он один) рисует на каждой странице подложку во весь лист:

```
rect x0=0 top=0 x1=596 bottom=842  stroke=False fill=True
```

`_vector_coverage` наносит все path-объекты на сетку и считает габариты связных кластеров.
Один объект во весь лист помечает все клетки → один кластер размером со страницу →
покрытие 1.0.

**Это ровно та же ошибка, что и половина B соседнего дефекта**
([PDF-EXTRACT-TOLERANCE-ARTIFACTS](pdf-extract-tolerance-artifacts.md)): там стратегия
`lines` строила рёбра таблиц из незаштрихованных заливок фона. Здесь — то же самое
принятие заливки фона за содержимое, воспроизведённое в новом коде в том же коммите,
который чинил первое.

## Почему тесты не поймали

Фикстура `figure.pdf` строится reportlab'ом, а reportlab подложку не рисует — на всех
синтетических страницах `stroke`/`fill` были такими, как ожидалось. Замеры в исходной записи
дефекта (42–85 % на страницах с таблицами) снимались тем же способом и потому тоже не
показали насыщения. Дефект видно только на файле от продюсера, который подложку рисует.

## Воспроизведение

| Документ | Продюсер | Подложек во весь лист | `vector_coverage` до фикса | после |
|---|---|---|---|---|
| 29 стр., сплошная проза | Skia/PDF m148 Google Docs Renderer | 1 на каждой странице | **1.000 на всех 29** | 0.000–0.836, по существу |
| 3 стр., Википедия | браузерная печать | 0 | 0.847 / 0.819 / 0.591 | без изменений |
| 9 стр., ELMA365↔3CX | без встроенных шрифтов | 0 | 0.101 / 0.000 / … | без изменений |
| 3 стр., фикстура с SVG | WeasyPrint 68.1 | 0 | 0.214 / 0.056 / 0.313 | без изменений |

```python
import pdfplumber
pg = pdfplumber.open("doc.pdf").pages[6]
objs = [*pg.lines, *pg.rects, *pg.curves]
print(len(objs), [(o["object_type"], o["stroke"], o["fill"]) for o in objs])
# 1 [('rect', False, True)]  -> единственный объект, и это подложка
```

## Побочная находка (исправлена тем же коммитом)

Предупреждение `text_layer_lossy` на stderr писало «OCR does not help — the glyphs were
never drawn» без оговорок. Для *текстового слоя* это верно, но читается как «здесь ничего
не восстановить», а это неправда: **текст внутри встроенных изображений не затронут**. На
документе, ради которого сигнал и вводился, диаграммы и скриншоты сохранили всю кириллицу,
и рендер страниц вернул бо́льшую часть содержимого. В `references/pdf-to-markdown.md` §3.9
оговорка была с самого начала, в самом предупреждении — нет. Текст предупреждения дополнен.

## Do-not

- **Не** выбрасывать из замера все незаштрихованные заливки подряд: заливка — законный
  способ рисовать фигуру (сектор диаграммы, залитый блок схемы). Отсекается только
  заливка **размером со страницу**.
- **Не** отсекать по одной лишь площади, без проверки обводки: рамка во весь лист — это
  нарисованный элемент, а не подложка, и её надо считать.
- **Не** считать порог по `char_count` подстраховкой, которую теперь можно ослабить:
  после фикса на страницах с плотной линовкой покрытие по-прежнему 0.55–0.84, и удерживает
  их именно текстовый конъюнкт.
- **Не** строить фикстуры только на reportlab: он не рисует подложек, и весь этот класс
  дефектов на нём невидим. Для замеров нужен файл от продюсера, который её рисует.
